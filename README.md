# 한번만 · Hanbeonman

> **한 번의 도움, 다음부터 스스로.**
>
> 내가 도와준 일을, 당신의 버튼으로 만드는 AI.

**한번만**은 사용자가 한 번 수행한 작업을 이해하고, 다른 사람도 반복해서 사용할 수 있는 **개인용 버튼**으로 바꾸는 서비스입니다. 버튼은 다음에도 유지할 조건을 기억하고, 날짜나 파일처럼 이번에 달라지는 내용만 물어봅니다.

현재는 **개발 기반 구현 단계**입니다. 한국어 웹 시작 화면, 사진 처리 도구, TAGO 고속버스 조회 어댑터와 조회 화면을 로컬에서 실행할 수 있습니다. 생성·공유·인증과 실제 외부 키를 이용한 운영 검증은 아직 남아 있습니다.

## 왜 만드는가

가족에게 온라인 조회나 파일 정리를 한 번 도와줘도, 다음번에 같은 설명이 필요할 때가 있습니다. 캡처된 설명은 현재 화면과 달라질 수 있고, 대신 처리한 결과만 전달하면 그 방법은 도와준 사람에게 남습니다.

한번만은 그 순간의 도움을 **받는 사람이 다시 쓸 수 있는 작은 앱**으로 남깁니다.

> “엄마, 다음엔 이것만 누르면 돼.”

첫 고객은 최근 한 달에 같은 디지털 작업을 두 번 이상 대신해준 가족입니다. 이후 개인의 반복 작업과 친구·동료에게 전달하는 작업으로 확장할 수 있습니다.

## 버스 전용 서비스가 아닙니다

제품의 단위는 교통편이나 특정 사이트가 아니라 **재사용할 작업과 그 작업의 입력·결과**입니다.

| 한 번 보여주는 작업 | 받는 사람의 버튼 | 구현 범위 |
| --- | --- | --- |
| 노선·시간대를 정해 공개 교통편 정보 조회 | 딸네 집 가는 차편 찾기 | TAGO 서버 어댑터·조회 화면 구현. 실제 데이터 검증 필요 |
| 사진 크기·형식을 정하고 파일로 만들기 | 사진 줄여서 파일 만들기 | MVP 기기 내 처리 예시 |
| 지역·요일·가격으로 수업 검색 | 내가 들을 수 있는 수업 찾기 | 후속 공개 조회 어댑터 |
| 생필품 옵션을 정하고 재주문 준비 | 우리 집 생필품 다시 주문하기 | 후속 인증·거래 연동 검토 |
| 계정에서 자료를 내려받고 정리 | 이번 달 자료 정리하기 | 후속 사용자 실행 환경 검토 |

MVP는 **공개 정보 조회와 사진 처리라는 서로 다른 두 작업 유형**을 같은 생성·검토·공유 흐름으로 지원하는 것을 목표로 합니다. 모든 사이트·앱을 자동으로 학습하거나 예약·결제·외부 전송을 수행하는 범위는 아닙니다.

## 어떻게 사용하는가

1. **한 번 보여주기** — 지원하는 웹페이지 또는 내장 사진 도구에서 작업합니다.
2. **버튼 만들기** — AI가 고정 조건, 매번 물어볼 값, 결과와 완료 기준을 제안합니다.
3. **확인하기** — 만든 사람이 내용과 공유 범위를 수정·확정합니다.
4. **전달하기** — 받는 사람에게 개인 버튼 링크를 보냅니다.
5. **다시 사용하기** — 받는 사람이 필요한 값만 입력하고 실행 결과를 확인합니다.

```text
딸네 집 가는 차편 찾기

서울 → 대전 · 오전 출발

언제 가실까요?
[ 가는 날짜 선택 ]

[ 차편 정보 보기 ]
```

위 화면은 개념 예시입니다. 조회 결과와 실제 좌석 확보·예약 완료는 구분합니다.

## 실행 방식

| 구분 | 만드는 사람 | 받는 사람 | 실행 위치 |
| --- | --- | --- | --- |
| 공개 조회 | PC Chrome 기록 확장 + 지원 웹페이지 | 모바일 웹의 입력 화면 | 등록된 서버 어댑터 |
| 사진 처리 | 내장 사진 도구에서 처리 방법 시연 | 모바일 웹에서 본인 사진 선택 | 받는 사람의 브라우저 |

공유 링크가 받는 사람의 다른 앱이나 제작자의 브라우저를 원격 조작하는 구조가 아닙니다. 제작자의 비밀번호·쿠키·로그인 세션을 전달하지 않으며, 사진 원본과 변환본은 기기 밖으로 업로드하지 않는 설계입니다.

MVP의 공유 링크는 **링크를 가진 사람이 사용할 수 있는 비공개 링크**입니다. 지정 가족의 신원을 보증하는 기능은 없으며, 소유자는 링크를 만료시키거나 회수할 수 있습니다.

## AI와 실행 엔진의 역할

- **AI:** 기록을 해석하고, 재사용할 값과 질문·화면·작업 명세 초안을 제안합니다.
- **만드는 사람:** 무엇을 고정하고 무엇을 물어볼지, 어디까지 실행할지 확인합니다.
- **실행 엔진:** 검증된 명세를 등록된 기능으로 수행하고 실제 결과를 확인합니다.

지원하지 않는 동작이나 예상 밖의 상태는 숨기지 않고 표시합니다. AI의 “완료했습니다”라는 문장만으로 성공을 판단하지 않습니다.

## 기술 스택과 준비

**TypeScript · Next.js/React · Tailwind CSS · Supabase PostgreSQL/Auth · Vercel**을 사용합니다. Chrome Manifest V3로 작업을 기록하고 Gemini API로 정제 이벤트를 작업 명세 초안으로 변환합니다. 초기 AI 평가 모델은 `gemini-3.1-flash-lite`입니다. 검증은 Zod·Vitest·Playwright, 자동 검사는 GitHub Actions로 구성합니다.

| 준비할 서비스 | 할 일 |
| --- | --- |
| [Supabase](https://supabase.com/dashboard) | `hanbeonman` 프로젝트(Healthy, Tokyo `ap-northeast-1`) 생성 완료. 인증·DB 스키마는 후속 연결 |
| [Vercel](https://vercel.com/signup) | `ptarowanb/hanbeonman`의 `apps/web`을 `web` 프로젝트로 연결·첫 배포 완료. Secret 값 입력 후 재배포 |
| [Google AI Studio](https://aistudio.google.com/apikey) | Google 계정으로 로그인하고 프로젝트의 Gemini API 키 생성. 실제 사용자 기록 처리 전 유료 API 조건 확인 |
| [공공데이터포털 TAGO 고속버스정보](https://www.data.go.kr/data/15098522/openapi.do) | 가입 후 개발계정 활용신청 |

설정 이름·입력 위치·배포 경계는 [SDD의 계정과 환경변수 준비](./SDD.md#63-계정과-환경변수-준비)를 따릅니다. 비밀 키는 채팅이나 Git에 올리지 않고 로컬의 `apps/web/.env.local`과 배포 환경변수에만 입력합니다. 계정 준비 없이 진행할 수 있는 개발 기반부터 구현합니다.

## 로컬 실행

Node.js 24와 pnpm 11.19.0을 사용합니다. pnpm이 없다면 `npm install --global pnpm@11.19.0`으로 설치할 수 있습니다. 저장소 루트에서 실행합니다.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

[로컬 시작 화면](http://localhost:3000)이 열립니다. 고속버스 조회 화면은 `/bus`, 사진 도구는 `/photo`에서 확인할 수 있습니다. TAGO 키가 없으면 조회 대신 설정 필요 상태를 표시하며, 가짜 시간표를 반환하지 않습니다.

```sh
pnpm typecheck
pnpm test
pnpm build
pnpm exec playwright install chromium
pnpm test:e2e
```

Linux CI에서 브라우저 시스템 의존성까지 설치할 때는 `pnpm exec playwright install --with-deps chromium`을 사용합니다.

커밋 전에 로컬 비밀 검사 훅을 한 번 설치합니다. 훅은 스테이징된 환경 파일과 알려진 비밀 패턴을 검사하며, 검사기를 찾지 못하면 커밋을 멈춥니다.

```sh
pnpm secrets:install-hooks
pnpm secrets:test
```

개발 키는 `apps/web/.env.local`에만 입력합니다. 이 파일은 Git에서 제외되어 있고, 배포할 때는 Vercel 환경변수에서 키별로 **Secret** 유형을 선택합니다. 실제 키를 커밋·채팅·로그에 넣지 않습니다. 상세한 환경별 분리와 유출 대응은 [SDD의 비밀 키 보관과 유출 방지](./SDD.md#65-비밀-키-보관과-유출-방지)를 따릅니다.

| 경로 | 현재 역할 |
| --- | --- |
| `apps/web` | 한국어 시작 화면과 환경변수 예제 |
| `packages/contracts` | 정제 이벤트·작업 명세·어댑터 정책·실행 상태 검증 |
| `packages/connectors` | TAGO 고속버스 요청 구성·응답 정규화·공급자 오류 구분 |
| `packages/photo` | 브라우저 사진 제한 검증·JPEG 변환 결과·로컬 ZIP 생성 |
| `tests/e2e` | 데스크톱·모바일 화면 검증 |
| `.github/workflows/ci.yml` | 설치·타입·테스트·빌드 자동 검사 |

기능별 작업 상태는 SDD 12절, 기반 작업과 TAGO 연동의 상세 계획은 [구현 계획](./docs/superpowers/plans/2026-09-09-foundation.md)과 [TAGO 연동 계획](./docs/superpowers/plans/2026-09-09-tago-integration.md)에 기록합니다.

## 사업 가설

첫 모델은 자녀가 결제하고 가족이 사용하는 이용권입니다. 무료 버튼 하나로 재사용을 경험하게 하고, 여러 버튼과 가족 공유·관리를 유료로 제공하는 방식을 검증합니다.

성공 기준은 버튼 생성 수보다 **받는 사람의 독립적인 완료율과 가족의 총 도움 시간 감소**입니다. 시장성·가격·유료 전환은 아직 검증되지 않았습니다.
