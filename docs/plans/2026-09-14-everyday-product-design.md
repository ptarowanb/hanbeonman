# 한번만 실사용 고도화 설계

작성일: 2026-09-14 · 상태: 11개 작업과 로컬 보관함 구현·통합 검증·Production 점검 완료. 계정·동기화·운영 및 실제 사용자 검증은 후속 범위.

핵심 흐름은 `요청 또는 템플릿 → 필요한 정보 질문 → 검토·수정 → 저장 → 실행 → 재사용·설정 전달`이다. 사용자 요청에 따라 기능별 한국어 커밋으로 구현한다. 현재 사용자 동작은 [SDD 16절](../../SDD.md#16-버전-20-로컬-생활-버튼-구현-기준)을 따른다.

## 채택한 방향

반복 사용 흐름을 먼저 완성했다. 외부 계정 없이 사용할 수 있는 로컬 보관함에 등록 작업을 모으고, 버스·사진 조건을 실제 실행 도구로 전달한다. 자유로운 요청은 Gemini가 11개 작업 계약으로 해석하며 템플릿과 짧은 작업명은 AI 호출 없이 처리할 수 있다. 계정·과금·기기 간 동기화와 임의 사이트 자동화는 각각 후속 출시 및 별도 어댑터 범위다.

## 구현한 기능

- **11개 생활 작업:** 날씨, 고속버스 시간표, 사진 압축, 체크리스트, 타이머, 디데이, 더치페이 계산, 단위 변환, 글 정리, 무작위 선택, 횟수 기록.
- **가벼운 시작:** `날씨`만 입력하면 지역을 묻고 `인천`이라는 답을 받아 초안을 만든다. 버스의 출발·도착, 타이머의 분, 정산 금액·인원도 필요한 값을 차례로 질문한다. 11개 템플릿은 AI 없이 편집기로 연결한다.
- **내 버튼:** 초안과 저장 버튼 이름·조건 편집, 고정 입력과 실행 입력 선택, 검색·종류 필터·즐겨찾기·복제·삭제 취소. 설명은 초안의 값을 유지한다. 저장 실패를 성공으로 표시하지 않고 최대 50개에서 기존 버튼을 자동 삭제하지 않는다.
- **버스·사진 실행:** URL로 노선·등급·요일·날짜 또는 사진 크기·품질을 전달한다. 버스는 정확한 이름·ID와 명시적 도시 별칭을 찾으며 모호한 이름이나 없는 등급은 사용자 선택을 요구한다. 목록 준비 후 유효한 조건만 한 번 자동 조회한다.
- **날씨 결과:** 현재 상태·체감온도·습도·바람, 제공되는 오늘 최저/최고·강수확률, 관측/조회 시각과 외출 준비 안내. 일부 추가 필드가 없어도 현재 날씨를 유지한다.
- **기기 내 실행:** 체크·타이머·횟수 상태를 버튼별로 보관한다. 타이머는 종료 시각 기준으로 남은 시간을 복원하며 페이지가 열린 동안 종료를 안내한다. 사진·글·계산 결과는 브라우저에서 처리한다.
- **백업·설정 전달:** 버전 있는 JSON 백업의 엄격한 검사·기존 데이터 유지 병합, URL fragment 설정 복사 링크의 검토 후 저장을 지원한다.

## 입력 계약

TypeScript·Next.js/React·Zod·Vitest·Playwright를 유지한다. 모든 작업은 `ButtonIntent`에 등록된 필드·타입·범위만 허용한다.

| 작업 | 주요 입력 범위 |
| --- | --- |
| `weather` | 도시 1~40자 |
| `bus_schedule` | 출발·도착 이름/ID, 선택 등급·유효 날짜·요일 정수 0~6 |
| `photo_compress` | 긴 변 정수 320~4096px, 품질 0.1~1, 사진은 도구에서 직접 선택 |
| `checklist` | 빈 줄 없는 1~20개 항목, 전체 200자 |
| `timer` | 정수 1~180분 |
| `dday` | 유효한 기준 날짜, 선택 일정 이름 |
| `split_bill` | 원 단위 정수 0~10¹², 인원 1~1000 |
| `unit_convert` | ±10¹² 이내 값, 같은 종류의 길이·무게·온도 단위 |
| `text_cleanup` | 기본 글 200자, 실행 글 20,000자, 공백 정리 또는 중복 줄 제거 |
| `random_pick` | 전체 200자·2~20줄, 서로 다른 후보 최소 2개 |
| `counter` | 1회 증감 정수 1~1000 |

## 보관과 전달 경계

`localStorage`의 기존 배열을 유지하고 `favorite`, `updatedAt` 메타데이터를 선택 필드로 읽는다. 이전 `generated-숫자` ID 버스 버튼의 빠진 출발·도착은 필수 실행 입력으로 보충한다. 이 마이그레이션을 백업이나 공유 링크에 적용해 외부 입력 검증을 완화하지 않는다.

저장 버튼은 최대 50개다. 로컬 직렬화와 백업 가져오기·내보내기는 UTF-8 **200,000바이트** 한도를 지킨다. 백업은 `{format:'hanbeonman-buttons',version:1,buttons:[…]}`이며 같은 ID는 기존 항목을 유지하고 새 버튼만 합친다. 크기·개수·내용·저장 오류 때 기존 자료를 보존한다. 백업에는 버튼 설정과 보관함 메타데이터만 담고 사진·체크·타이머·횟수 상태는 담지 않는다.

설정 복사는 `/create#button=encodeURIComponent(JSON.stringify(createIntent))`를 사용한다. 인코딩된 fragment는 약 16KB 이하로 제한한다. 링크는 검토할 초안을 전달하며 저장 전 자동 실행하지 않는다. 수신자의 복사본은 원본과 독립적이고 **회수·원격 수정·만료·수신자 신원 확인을 지원하지 않는다.** 서버 토큰 기반 공유와 구분한다.

## 구현 수용 기준

- [x] `날씨 → 인천` 질문·초안·저장·실행과 실제 날씨 결과
- [x] 11개 템플릿, 저장 조건 편집, 버스·사진 실행 조건 전달
- [x] 체크리스트·타이머·디데이·정산·단위 변환·글 정리·선택·횟수 실행
- [x] 검색·즐겨찾기·복제·삭제 취소·백업·설정 링크 검토 및 복원
- [x] 잘못된 계약·범위·백업과 저장 실패의 원본 보존 검사
- [x] 단위 214개, Chromium 데스크톱·모바일·320px 전체 E2E 기준선 102개와 후속 접근성 회귀 3개(총 105개), 타입·빌드·비밀값·스키마 검사 통과
- [x] 기능별 커밋·푸시 및 새 Production의 11개 템플릿·질문·저장·실제 실행 점검

추가 회귀 검사의 최신 수치는 SDD 16.7절에서 갱신한다. 테스트 통과와 배포 확인은 실제 가족 사용자나 사업성 검증을 의미하지 않는다.

## 계정 기반 완성본의 후속 출시 기준

Supabase Auth와 owner_id RLS로 로그인·계정 복구·저장·다중 기기 동기화를 연결한다. 기존 로컬 버튼은 사용자가 선택해 계정으로 복사하고 UUID·updatedAt으로 충돌을 처리한다. 회수 가능한 공유는 서버 토큰·발행 버전·만료 정책을 별도로 구현한다.

계정 탈퇴·데이터 삭제, 분산 환경의 지속적인 API 사용량 제한, 오류 관측·비용 상한과 실제 가족의 반복 사용 관찰을 출시 판정에 포함한다. 이번에 구현한 반복 사용 가능한 로컬 버전과 후속 계정·운영 범위를 완료 여부에서 구분한다.
