# 자연어 버튼 생성 구현 계획

## 목표

사용자가 “인천 날씨 알려주는 버튼 만들어줘”처럼 작업을 설명하면, Gemini가 임의 코드를 생성하지 않고 `actionRegistry`에 등록된 작업의 버튼 초안을 제안한다. 필수값이 빠지면 명세에 정의된 값만 질문하고, 제작자가 미리보기를 확인한 뒤 저장·발행한다. 버튼 실행은 기존 어댑터가 담당하며 실행 시 Gemini를 호출하지 않는다.

## 범위

- 1단계는 `weather`, `bus_schedule`, `photo_compress` 세 등록 작업의 자연어 해석 계약과 날씨 버튼 생성 데모다.
- 날씨는 도시를 고정값으로 저장하고 실행 시 추가 입력이 없는 버튼을 지원한다.
- 버스는 출발지·도착지·등급을 고정값으로 제안하고 날짜를 실행 입력으로 남긴다. 터미널 이름은 TAGO 목록으로 서버에서 ID를 확인한다.
- 사진은 변환 규칙을 고정하고 수신자 사진만 실행 입력으로 남긴다.
- 초기 저장은 현재 인증 미연결 범위에 맞춰 브라우저 localStorage를 사용하고, 영속 저장 연결 시 `workflow_versions.spec`으로 이전한다.
- 임의 URL·스크립트·DOM 선택자·로그인·결제·송금·외부 전송은 생성 대상에서 제외한다.

## 계약

Gemini 출력은 다음 네 가지 의도 중 하나다.

- `create_button`: 작업 종류와 고정·실행 입력 후보가 모두 해석됨
- `clarify`: 등록된 필수 필드가 빠져 질문이 필요함
- `run_now`: 버튼 생성이 아닌 즉시 실행 요청으로 해석됨. 저장하지 않고 실행 확인을 요구함
- `unsupported`: 등록 작업으로 표현할 수 없거나 권한 범위를 넘음

출력은 JSON Schema와 Zod로 검증한다. `actionKind`는 `actionRegistry`의 열거값만 허용하고, 고정값·질문·제목은 길이와 필드별 범위를 검사한다. 모델의 설명·신뢰도만으로 실행 여부를 결정하지 않는다.

## 구현 순서

### 작업 1: 자연어 해석 계약

1. `packages/contracts`에 `ButtonIntent`·`ButtonDraft`·누락 필드 계약과 허용 의도를 추가한다.
2. `actionRegistry`에서 모델에 전달할 작업·입력 필드 목록을 결정적으로 만든다.
3. 정상 생성, 누락 도시, 미지원 결제, 임의 필드·URL 거부 테스트를 먼저 작성한다.

검증: `pnpm test -- packages/contracts`와 `pnpm typecheck`.

### 작업 2: Gemini 서버 어댑터와 해석 API

1. `GEMINI_API_KEY`·`GEMINI_MODEL`을 서버에서만 읽는 커넥터를 만든다.
2. Gemini Structured Outputs에 고정 JSON Schema를 보내고 응답 텍스트만 파싱한다.
3. 타임아웃, HTTP·계약 오류, 키 미설정을 안전한 상태로 변환한다. 키·원문·요청 URL은 응답·로그에 넣지 않는다.
4. `POST /api/buttons/interpret`는 인증된 제작자의 자연어를 받아 계약 결과만 반환한다. 이 API는 저장·실행하지 않는다.

검증: fetch mock으로 성공·`clarify`·`unsupported`·실패·타임아웃 테스트, 실제 키 없이 빌드·시크릿 검사.

### 작업 3: 자연어 입력과 누락값 질문 UI

1. 제작자 화면에 작업 요청 입력창과 `버튼 만들기`를 추가한다.
2. `clarify` 결과의 누락 필드만 입력 컨트롤로 보여주고, 답변을 포함해 다시 해석한다.
3. `create_button` 결과는 제목·고정값·실행 때 물어볼 값·실행 위치·경계를 미리 보여준다.
4. `unsupported`·`run_now`·실패는 저장 버튼 없이 이유와 다음 행동을 안내한다.

검증: Playwright에서 날씨 생성, 도시 누락 질문, 미지원 요청 차단, 로딩·재시도 상태를 확인한다.

### 작업 4: 초안 저장과 기존 어댑터 연결

1. 확인한 초안을 `ButtonDefinition`으로 변환하고 localStorage에 버전과 함께 저장한다.
2. 날씨 버튼을 누르면 고정 도시를 `/api/weather`에 전달한다. 실행 시 Gemini를 호출하지 않는다.
3. 버스 초안은 터미널·등급 ID를 서버에서 재확인하고 날짜만 실행 입력으로 받는다.
4. 이후 Supabase 연결 시 동일한 명세를 `buttons`와 `workflow_versions`에 저장하고 기존 검토·발행 계약으로 넘긴다.

검증: 저장·새로고침·삭제·한 번 실행, 잘못된 명세·중복 실행·어댑터 오류 테스트.

### 작업 5: 문서·배포 검증

1. README·SDD에 실제 구현 범위와 미지원 경계를 기록한다.
2. `pnpm test`, `pnpm typecheck`, `pnpm build`, `pnpm test:e2e`, `pnpm secrets:check`를 실행한다.
3. 기능별 한글 커밋을 만들고 `main`에 순서대로 푸시한다.

## 보안·운영 기준

- 자연어 원문은 Gemini 입력에 필요한 최소 기간만 사용하고 실행 기록에는 확정 입력만 남긴다.
- 사용자 문장과 외부 페이지 문구는 데이터로 취급하며 시스템 지시로 승격하지 않는다.
- 모델이 반환한 `actionKind`, 필드, URL, 코드, 권한을 서버가 그대로 신뢰하지 않는다.
- 생성 요청당 Gemini 호출 횟수와 입력 길이를 제한하고, 실행 요청에는 Gemini 비용이 발생하지 않게 한다.
- 공개 버튼은 검토·발행된 버전만 실행하며, 미리보기 초안은 실행할 수 없다.
